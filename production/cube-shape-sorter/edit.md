## 3. Сведение (`audio/mix.py`)

1. **Голос** — основа, моно → стерео с панорамой.
2. **Музыка**:
   - сайдчейн под голос: детектор attack 5 мс / release 150 мс, провал до −6 дБ, когда огибающая голоса ≥ −20 dBFS;
   - плановые провалы §5.2: 2.6 −4 дБ на 0.2 с, 5.0 −8 дБ на 0.3 с, 11.0 −3 дБ на 0.3 с.
   - Итог: музыка на 11–25 дБ ниже вокализаций (LUFS на отрезке каждой вокализации).
3. **SFX** — шина −4 дБ. Пик-фактор ударов ≈ 17 дБ, и без этой поправки −14 LUFS
   получаются только за счёт лимитирования всех трёх больших ударов до одного потолка.
4. **Мастер**:
   - общий гейн +8.5 дБ, его подбирает итерация до −14.00 LUFS;
   - true-peak лимитер: ×4 оверсемплинг, lookahead 5 мс, release 80 мс, потолок −1.3 dBTP;
   - огибающие лимитера и дакинга считаются по кругу, поэтому шов не даёт ступенек.

### 3.1 Замеры `audio/mix.wav`

| Метрика | Значение | Цель |
|---|---|---|
| Integrated (ffmpeg ebur128) | **−14.0 LUFS** | −14 ±1 |
| True peak (ebur128 peak=true) | **−1.3 dBTP** | ≤ −1.0 |
| loudnorm print_format=json | input_i −14.21, input_tp −1.26 | — |
| LRA | 5.4 LU | — |
| Музыка, short-term в т.1–3 (с дакингом) | −23.9 LUFS | ≈ −22 |
| Работа лимитера | макс. −5.0 дБ, суммарно 1.7 с из 15 | — |

Лимитер давит в основном на удары 2.6 (−4.4 дБ) и 5.0 (−4.6 дБ).

Иерархия ударов по громкости (K-взвешенная, окно 100 мс после удара):
**5.0 (−3.2) > 2.6 (−5.8) > 0.4 (−8.4) > 11.0 (−15.3)**, как требует §5.6.

После AAC (тестовый mp4): −14.0 LUFS, −1.2 dBTP.

### 3.2 Шов петли (`audio/check_loop.py`: mix.wav склеен сам с собой)

| Проверка | Значение | Вывод |

## 4. Цвет (`render.sh`, direction §2.8)

`vignette=angle=PI/12, eq=saturation=1.04, noise=alls=2:allf=t`, затем перевод в bt709
(tv range) и yuv420p.

**Отклонение по виньетке.** В §2.8 стоит `PI/6`. Но у ffmpeg на кадре 9:16 это затемняет
угол на ≈ 44 % (замер на `test/f_0012`), а не «едва заметно». Поэтому взят `PI/12`:
≈ 15 % в углу, ≈ 12 % у верхнего/нижнего края, ≈ 4 % у боковых (замер QA по final.mp4).

Остальная палитра (`#FF8A2A`) задана в 3D, в посте её не трогаем. Проверка ±10 % на
кадре 30 ждёт полного рендера: в `test/` кадра 30 нет.

## 6. Экспорт (`render.sh`)

```
./render.sh                 # render/frames/f_%04d.png + audio/mix.wav → final.mp4 + loop_check.mp4
./render.sh --test OUTDIR   # слайдшоу из 11 тестовых кадров → OUTDIR/test_slideshow.mp4
```

- **Видео:**
  - H.264 High, `-preset slow -tune animation -crf 18`, yuv420p;
  - 30 fps CFR, GOP 60, ровно 450 кадров;
  - теги bt709.
- **Звук:** AAC 320k, 48 кГц, стерео. `+faststart`.
- **Отклонение по CRF.** В direction §8.4 стоит CRF 16. Взят CRF 18 по задаче этапа.
  Вернуть 16 можно правкой одного флага.
- **Самопроверка в скрипте:**
  - ffprobe: кодек, профиль, 1080×1920, yuv420p, число кадров = 450;
  - ebur128 по звуку mp4: −15…−13 LUFS и ≤ −1 dBTP;
  - склейка `final.mp4` ×2 → `loop_check.mp4` для просмотра шва 449 → 0.
- **Если кадров не 450**, скрипт останавливается с ошибкой и подсказкой.

**Тест на 11 кадрах** (scratchpad, не production):

| Параметр | Результат |
|---|---|
| Видео | h264 High, 1080×1920, yuv420p, bt709, 30/1, 450 кадров |
| Звук | aac 48 кГц стерео |
| Длительность | 15.000 с |
| Громкость | −14.0 LUFS, −1.2 dBTP |
| Время сборки | 72 с |

Фактический битрейт AAC — 268 кбит/с при цели 320k. Энкодер ffmpeg недобирает его на
разреженном материале. Флаг стоит верно.
